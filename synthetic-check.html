T04 합성 실패 검사대

과제 4 · 카드 3 — 다섯 가지 실패를 공개 결정론 fixture로 재현합니다. 여기서 쓰는 값은 전부 합성(가짜) 데이터이며, 실제 서울 기온·실제 날짜 기록과는 무관합니다.

이 페이지는 저장·실패·복구 계산 로직만 검사합니다. 실제 공개 원천 조회 화면은 서울 기온 계기판 쪽이며, 두 페이지의 데이터는 서로 다른 저장소에 분리되어 있어 여기서 무엇을 눌러도 실제 기록에는 영향이 없습니다.

공개 합성 검사 꾸러미

package_id—
contract_version—
정본 조건 수—
파일 SHA-256 대조17개 파일 모두 asset-manifest.json과 일치 확인 (2026-09-17)

① 정상 흐름 — D1-A → D1-B → D2

가상 1일차(2건) → 가상 2일차(1건), 전일 대비 +15

reset → T04-NORMAL-D1-A → T04-NORMAL-D1-B (같은 행 갱신) → T04-NORMAL-D2 (새 행)

값 100으로 첫 행 생성 → 같은 날 105로 갱신(행 수 그대로) → 다음 날 120으로 새 행 생성, 전일 대비 +15 계산.

② 다섯 가지 실패 — 각 reset → D1-A → D1-B → 실패 1건

느린 외부 응답 (timeout)

→ T04-TIMEOUT

출처 응답이 제한 시간보다 늦게 옵니다.

401/403 거절 (auth)

→ T04-AUTH-401

외부 데이터 출처가 인증을 거절합니다. (제출물 자체의 로그인과는 무관)

호출 제한 (rate_limit)

→ T04-RATE-429

출처가 429와 함께 Retry-After를 돌려줍니다.

오프라인 (offline)

→ T04-OFFLINE

네트워크 연결 자체가 끊깁니다.

응답 형식 변경 (schema_error)

→ T04-SCHEMA-BREAK

HTTP는 성공(200)이지만 값의 타입이 바뀌어 정규화에 실패합니다.

③ 오류 뒤 회복 — timeout → 재시도 성공

다시 시도 행동 → fresh/none 복구, 다음 날짜 새 행 추가

reset → D1-A → D1-B → T04-TIMEOUT (stale/timeout) → [다시 시도] → T04-RECOVER-D2

타임아웃 직후 상태(stale/timeout, 값 105 유지)를 먼저 보여준 뒤, 복구 fixture를 재생해 fresh/none·값 120·전일 대비 +15로 돌아오는지 확인합니다.
